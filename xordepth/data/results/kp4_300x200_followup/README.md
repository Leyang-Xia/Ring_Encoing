## 搜索覆盖

- 矩阵有 300 个互不相同的非平凡输出。每次 Beam 转移至多新增一个节点，只有全部输出都已有单项表示才能调用 `export_circuit()`。即使宽度为 1，每条路径也至少需要 300 次转移才有机会完成。在 256 状态的协议内，Beam 独立发布完整 KP4 电路在结构上就不可达。这个下限只用于检查预算。
- 根状态有 19849 个不同的行内输入对，两种深度上限都允许它们。非零 seed 在 `expand_state()` 内打乱整个候选列表，再取有限的 branch。新增类型与普通 pair 共用这些位置，候选生成数和真正扩展数是两种不同的度量。
- 单独在深度 8、13 尝试给 pair 组增加 `--residual-pairs 4 --residual-targets 2`。两次都主动终止，没有完整结果。源码中的 bridge 先生成跨行的每个不同操作数配对，再排序、保留 4 个。按矩阵逐列计数，根状态即有 304508219 条带目标位置的记录。计算式为所有行对的权重乘积之和减去各列出现次数的二项系数之和。本机构建每条记录 64 字节，仅记录内容即约 18.15 GiB，物理内存为 16 GiB。该数字为构造规模推算。
- 优先验证两处改动的收益。首先为部分 Beam 状态接入深度可行的共享 CSE 收尾，按完整电路的活门数评分，并保留前一档已验证电路。其次在生成 bridge 时直接维护有限候选，给普通 pair 和跨表示候选分别预留扩展名额。对照时固定 seed、状态数和收尾次数，分别记录完整候选数、深度超过 8 的候选数及其中的最低门数。

复核单档可从仓库根目录运行：

```sh

```
