# 深度硬约束下的门数优化 V2

目标：最小化实际存活 XOR2 门数，最大输出深度不超过 D。算法是有界启发式，不承诺全局最优。

## 使用

```sh
make -j3
./build/ringlab analyze xordepth/data/matrices/cauchy_7_4_direct.txt \
  --method OUR_DCCSE_V2 --depth 5 --seeds 8 --seed 1 --output /tmp/v2.json
./build/ringlab verify --input /tmp/v2.json --samples 0
```

可加 `--incumbent FILE`，FILE 为同一目标变换的完整线路 JSON 或 `xordepth frontier` 结果。每条载入线路均验证输入宽度、完整 GF(2) 目标和存活门数；只选择深度不超过 D 的候选。不同目标线路被拒绝，不会悄悄参与比较。历史线路优化预算不计入本次优化耗时，必须明确标注。

## 算法

1. 运行深度可行的共享提取，两种策略各运行 N 个种子：原贪心和已有有限前瞻。总计 **2N** 次，不是 N 次。两者仍进行原有局部替换；选最少门线路，平局优先较浅。
2. 从所有输出的截止深度 D 逆向传播每个节点的最晚到达层数，允许非关键路径消耗剩余深度余量。
3. 尝试删除一个非输出的共享门，并同时重建其全部使用者。每个受影响门以准确 GF(2) 掩码寻找较早可用的二输入等价表达式；整个事务可包含多个本身不省门的替换。重建时复用相同掩码节点，随后剪除无用门。
4. 只有完整线路验证通过、实际门数严格减少且最大输出深度不超过 D 时才接受事务。最多400个删除尝试、4轮，搜索预算是有限的。不是任意片段精确综合，也没有使用 SAT。
5. 若提供已有候选，在独立合成结果和所有可行候选中按门数选择，再进行相同改写。保留初始可行线路，门数不会因后处理变差。

`original_ours_cost` 为当前参数下第一种策略结果；`standalone_cost` 为不载入历史线路的组合与改写结果；`initial_source` 记录选中的历史候选来源，或 own synthesis；`cost` 为最终门数。默认不加 `--lookahead` 时第一种策略即旧 OUR_DCCSE。V2 自动尝试另一种策略。`--no-refine` 只关闭旧策略内的单门优化，V2多使用者改写仍执行。

## 限制与验证

深度为 XOR2 拓扑深度，输入层为0，接线和别名免费，不计扇出和布线延迟。只搜索有限的双信号替代表达式与门删除，不穷尽 GF(2) 线路。外部 `timeout 180` 是本次实验墙钟保护；程序尚未实现中途保存 incumbent 的 anytime 接口。

测试覆盖需联合改写两个使用者才能省门、使用额外深度余量换门数、零预算、输入深度拒绝、随机矩阵功能与单调门数、200位掩码以及CLI载入和验证。Make/CMake无需新增源文件：均已包含原 depth_cse.cpp。
