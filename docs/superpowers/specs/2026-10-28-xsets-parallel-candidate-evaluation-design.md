# X-Sets 候选评估并行化设计

## 目标

降低高参数 `MW_SQ`、以及后续可复用到 `MW_SMALLEST_SUM` 的墙钟运行时间，同时保持现有 X-Sets 调度逻辑的可重放性。这里的“逻辑相同”采用严格定义：同一输入、方法和参数下，候选的枚举顺序、评分规则、平局处理、最终调度线路、XOR 数和验证结果都保持不变；并行化只改变候选评估完成的先后顺序。

## 现状与瓶颈

`Schedule::GetBest` 在 `MW_SQ` 分支中按 `Edges_By_Weight[top]` 的有序集合遍历候选。对每个候选，它会：

1. 深拷贝当前 `Schedule`；
2. 加入候选并反复执行 `Find_Two`/`Add_Element`；
3. 读取模拟状态的最高 edge weight 和候选数量作为评分；
4. 删除模拟状态。

各候选的模拟状态互不依赖，但目前完全串行。因此高参数主要把时间花在多个独立的深拷贝和前瞻重放上，而不是最终选中候选的应用上。

## 方案

### 候选快照

进入 heavyweight 分支后，主线程先把当前最高权重层按现有 `std::set` 顺序复制为 `vector<string>`。每个候选仍使用原始字符串和原始位置编号；不改用 `unordered_set`，不改变排序。

对每个候选建立独立的 `Schedule`：调用现有 `Copy(me)`，构造候选 `Bitset`，执行与串行实现完全相同的 `Add_Element` 和 `Find_Two` 循环，然后只提取评分所需的整数。候选线程不写共享的 `me`、全局调度状态或其他候选的对象。

### 工作线程与确定性归并

使用 C++17 标准库线程设施。线程数由环境变量控制，默认使用硬件并发数，并限制为候选数；设置为 `1` 时保留串行路径，便于回归和基准对照。线程池只负责分发候选索引，避免为每个候选反复创建线程。

每个 worker 将结果写入与候选位置一一对应的结果数组。主线程等待全部结果后，严格按原候选顺序执行现有比较：

- `MW_SQ` 仍最大化 `(newtop, newn)`；
- `MW_SMALLEST_SUM` 仍最小化 `sum`；
- 相同评分仍按原候选顺序进入 `pots`，因此 `maxelts` 截断结果不变。

归并阶段不依赖 worker 完成顺序，也不在 worker 中修改 `pots`、`maxtop`、`maxn` 或 `minxsz`。

### 异常和资源生命周期

每个任务使用 RAII 管理 `Schedule` 和临时 `Bitset`。若某个任务抛出异常，主线程在 join 后重新抛出，并保持命令失败语义；不会返回部分候选。候选结果只保存评分和原始位置，不跨线程传递拥有权不明的 X-Sets 指针。

## 线程安全边界

本方案只并行 heavyweight 候选模拟。候选模拟读取全局 `Technique`、`Thresh` 等配置，但不修改它们；`Schedule::Copy` 复制所有可变容器和内部对象，`Add_Element` 只操作该副本。包含 `std::rand()` 的图匹配路径不在 `MW_SQ`/`MW_SMALLEST_SUM` 并行区内。若审计或运行时检查发现第三方代码存在共享可变状态，自动退回单线程路径。

## 不改变的行为

- 最高 edge weight 层和候选集合不变；
- `Schedule::Copy`、`Add_Element`、`Find_Two` 的状态转移不改写；
- `UBER_XSET`、`MW`、`MW_SS`、`MW_MATCHING`、`SUBEX` 保持原路径；
- 输出线路的门顺序、目标顺序、计算历史和 XOR 计数保持不变；
- 现有命令行参数含义不变，只增加可选的线程数控制；
- X-Sets 原版权和输入输出格式保持不变。

## 验证计划

### 语义等价

对固定矩阵和参数分别以单线程、并行线程运行，逐项比较：

1. 完整输出文本（安静模式下的线路和 XOR 计数）；
2. `ringlab analyze` 生成的 JSON 中的线路、成本和验证状态；
3. 逐门计算历史及目标输出；
4. 多次重复运行的摘要，检查确定性。

覆盖 `MW_SQ` 和 `MW_SMALLEST_SUM`，并确认 `UBER_XSET` 输出不受影响。

### 性能

在已有 `100x50` 确定性矩阵以及 8 位域到 17 维环的高参数输入上，记录线程数为 1、2、4 和硬件并发数时的墙钟时间、峰值内存、完成状态和 XOR 数。超时只记录为超时，不把它解释为算法质量结论。

### 回归

运行现有 `make test`、X-Sets 安静模式测试、ASan 构建（若环境提供）以及固定输入重复运行。任何线路或 XOR 数差异都视为实现失败，先退回单线程并定位原因。

## 非目标

- 不改变 X-Sets 的评分函数、搜索空间、随机策略或参数含义；
- 不把候选评估改造成近似评分或共享可变增量状态；
- 不在本阶段并行最终调度步骤，也不改变 `UBER_XSET` 的算法；
- 不声称并行化降低 XOR 数，它只应降低运行时间。
