# 环提升编码的可行性验证方案

本文配合[数学基础](mathematical-foundations.md)，设计一组可以逐步执行、彼此校验的研究实验。目标不是只找到一个漂亮的 XOR 数字，而是判断：环提升在什么条件下有收益，收益是否来自可复用的计算结构，以及获得这些收益的代价是否值得。

方案先从不依赖硬件性能的数学与电路实验开始，再进入真实编码和运行时间测试。建议按阶段推进，每一阶段都留下可以独立检查的证据。

阶段性进展：第一轮构造了一个[四位域到五维循环环的 35 次 XOR 电路](existence-example.md)，曾优于最初检查的基线；补充 MW_SQ 与 UBER_XSET 后，最好直接路径已降至 32 次。因此，该实例目前尚未提供相对于新增强基线的净收益。全部电路和验证脚本均已保留；预算公平比较、留出确认集和工程性能验证仍待执行。

后续存在性搜索找到[八位域到十七维循环环的新实例](structured-ring-example.md)：主计算 152 次、投影 51 次，总计 203 次，优于已完成直接基线中的 212 次。已保存完整电路及验证材料，未完成和超时配置仍单独列出；这不代表本方案其余阶段已经完成。

第二轮[扩展搜索记录](structured-ring-family.md)延长了 MW_SQ 搜索，并用保持 MDS 性质的行、列缩放构造更多实例。新记录同时保留了有限域分解基线，避免只与不识别缩放结构的通用调度器比较；跨实例的统计稳定性、同预算比较和工程性能仍未完成验证。

后续主实验限定未缩放 Vandermonde 校验矩阵 $A_{ij}=x_j^i$，优先使用固定域表示、连续幂取点和有代表性的码参数。其他 MDS 矩阵与行、列缩放另列扩展结果。每个实例内固定编码任务，仅搜索环、提升和电路调度，禁止用修改编码矩阵本身的收益代替实现收益。

对应的[主实验结果与预算](vandermonde-validation.md)单独维护；搜索器默认检查实际矩阵的 Vandermonde 幂关系，只有显式选择才扩展到缩放矩阵。

## 1. 首先分清：我们要验证哪几种“可行”？

固定不可约多项式 $P$、编码矩阵 $A$ 及其二进制展开 $T_A$。选择 $Q$，令 $R=\mathbb F_2[t]/(PQ)$。选定系数提升后得到 $B_G$，投影矩阵为 $D_m$。

代数正确性要求

$$
D_mB_G=T_A.
$$

在此基础上，分别研究以下命题。

| 问题 | 要得到的证据 | 不能据此声称什么 |
|---|---|---|
| 计算是否正确？ | 矩阵恒等式、调度符号执行、实际数据对照全部一致 | 正确不等于省 XOR |
| 是否存在有收益的实例？ | 至少一条完整、正确、总 XOR 少于指定直接路径的电路 | 一个实例不等于普遍有效 |
| 收益是否来自表示与复用？ | 控制搜索预算、投影策略后，消融实验仍能定位收益来源 | 比一次弱基线好，不等于环结构本身有独特优势 |
| 是否对实际编码有价值？ | 在未参与调参的 RS、Cauchy 校验矩阵上有稳定收益 | 随机矩阵上的结果不能直接代表纠删码 |
| 是否值得付出搜索成本？ | 相同 CPU 时间下有更好的电路，或离线代价能被使用次数摊销 | 搜索更多候选得到更好结果，不自动意味着搜索方法更高效 |
| 是否能提高程序性能？ | 包含数据转换和投影的端到端吞吐实测改善 | XOR 减少不自动意味着运行时间下降 |

本文中的“有收益”必须说明相对于哪条基线。所有结论都限定在已测矩阵、环、算法和预算范围内。

### 1.1 保留一个理论边界

记 $C_\oplus^*(T_A)$ 为原变换在固定成本模型下的真正最少 XOR 数。任何正确的环路径本身也是实现 $T_A$ 的电路，因此不能少于这个值。

所以，小规模精确求解用于校准“我们离真正最优还有多远”，而不是寻找一条击败原问题最优值的环电路。后者在相同模型下不可能发生。

如果实验出现“环电路少于已经证明的直接最优值”，应优先排查计数、投影、输出坐标或精确模型是否不一致。

## 2. 统一成本与实验规则

### 2.1 电路成本

第一阶段使用与数学基础相同的模型：二输入 XOR 每个算 1 次，复制、接线、常量零和坐标置换不计 XOR，已计算的值可以被多次复用。

每个结果都必须附带电路，而不只附一个计数。一个电路由输入、逐条 XOR 指令以及完整输出映射组成。零输出、直接复制输入的输出、重复输出都必须得到明确处理。

将最终电路的输入坐标和输出坐标固定为原有限域的标准多项式坐标。若使用其他输入提升、换基或输出转换，相应计算必须进入总电路。

对分阶段实现，记录

$$
C_{\rm ring}=C_{\rm input}+C_{\rm main}+C_{\rm projection}+C_{\rm output}.
$$

标准补零输入的 $C_{\rm input}=0$。通常原坐标投影已经产生最终输出，此时 $C_{\rm output}=0$。

先计算所选分阶段实现的投影成本，可得到一个收支条件：在没有其他转换成本时，只有 $C_{\rm main}<C_{\rm direct}-C_{\rm projection}$ 才能获益。如果所选投影电路本身已不小于直接基线，这个分阶段候选不必继续搜索。这个筛选针对已选成本与实现，不是排除所有其他投影电路，更不适用于允许跨阶段抵消的联合电路。

对联合优化实现，以上分项可能共享门，不能机械相加。应对最终 DAG 去除无用计算后，直接统计实际 XOR 门的总数。

### 2.2 两种比较都要做

**机制比较：** 给每个候选使用相同的后端调度器及同样的单次配置，观察提升如何改变候选电路。它适合解释机制，但环路线可能尝试了更多候选。

**方法比较：** 直接路线和环路线各有相同的累计 CPU 时间预算。环路线的 $Q$ 筛选、提升搜索、候选调度和联合优化都计入预算。它回答“花同样的搜索时间，哪条路线更划算”。

若预计算能被多个编码矩阵复用，分别报告首次使用成本和摊销后的成本，不把预计算隐藏起来。

### 2.3 建议的默认预算

以下是控制实验规模的起点，不是性能结论或硬性理论阈值：

- 探索阶段：每矩阵、每条路线累计 10 个 CPU 秒。
- 确认阶段：每矩阵、每条路线累计 60 个 CPU 秒。
- 随机搜索可分成 10 次重启，共享上述总预算；重启不是额外赠送的预算。
- 默认固定为单线程，记录 CPU 时间与墙钟时间。若改为多线程，明确记录核数并按 CPU 总量比较。
- 小规模精确求解单独设超时，例如每个实例 60 秒；超时必须标记为未知，不当作求解成功或失败。

在固定硬件上先跑最小闭环，检查这些预算是否能完成有意义的候选比较，然后冻结正式配置。若更换预算，需要两条路线一起调整，并保留原结果。

## 3. 阶段一：先建立可信的验证工具链

### 3.1 独立代数参考实现

建立一个小而清楚的参考实现，直接按多项式乘法和带余除法计算，不复用被测程序的乘法、约简或 bitmatrix 生成代码。

参考实现负责检查：

1. $M=PQ$ 的无进位多项式乘积是否正确。
2. 四类对象的表示是否一致：域系数、环系数、输入比特顺序、输出比特顺序。
3. 每个提升是否满足 $\widetilde a\bmod P=a$。
4. 单个乘法块是否等于逐个输入基向量计算得到的结果。
5. 投影矩阵第 $\ell$ 列是否等于 $t^\ell\bmod P$ 的坐标。
6. 整体是否满足 $D_mB_G=T_A$。

对 $w\le4$ 的小规模情形，枚举全部输入和提升，覆盖互素与不互素两类 $P,Q$。对较大情形，精确核对矩阵恒等式，并补充随机数据、单比特输入、全零和全一输入。

矩阵恒等式已经证明了对应线性变换在所有输入上相等；随机数据测试用于检查实际序列化和执行路径，不替代恒等式检查。

### 3.2 调度符号执行

给第 $j$ 个输入赋一个只有第 $j$ 位为 1 的符号掩码。每条 XOR 指令就对两个掩码做 XOR。最终输出掩码必须逐行等于 $T_A$。

这样能够同时发现：漏算投影、输出顺序错误、错用临时变量、错误的零输出处理，以及“打印的 XOR 数正确但输出电路错误”。

计数直接来自被执行的 XOR 指令数，与程序自己打印的计数再作交叉核对。候选未通过验证时，不参与性能排名。

### 3.3 在当前仓库中应先处理的实验障碍

以下是后续实现验证工具链时的前置任务，当前方案不把已有可执行程序视为无误的测量器：

- 修复 `Uber.cpp` 中释放 `t` 后读取 `t->Min` 的行为，并通过 AddressSanitizer、UndefinedBehaviorSanitizer 和原触发样例复查。
- 修正直接 XOR 基线始终读取固定原矩阵文件的问题；基线计数应由实际传入矩阵计算。
- 让直接路径和环路径的调度参数显式可配置，避免一条路线使用交互选择的级别、另一条固定使用级别 2。
- 将 X-Sets 的时间种子替换成可记录、可重放的显式种子。
- 对空目标、单位向量目标、重复目标及矩形矩阵，检查计数和完整输出映射。
- 优化器超时、异常退出、解析失败时明确报告失败，不将失败当成 0 XOR 或继续输出胜负百分比。
- 确认 GF-Complete、Jerasure 与自定义实现使用相同的原域多项式和坐标约定。

**阶段通过条件：** 所有保留的候选均有独立的矩阵与调度验证；没有尚未解释的结果不一致。若发现错误，先解决测量问题，再做收益结论。

## 4. 阶段二：用小规模问题观察收益，并用精确解校准

这一阶段把“候选空间是否值得搜索”和“搜索算法有没有找好”尽量分开。

### 4.1 从足够小的参数开始

建议使用 $w\in\{2,3,4\}$，先选 $k\in\{1,2\}$、$m\in\{1,2\}$，并以 $r=1,2$ 为主。

对固定 $P,Q,A$，逐位置提升共有

$$
2^{rmk}
$$

种。例如 $w=3,k=2,m=1,r=2$ 时只有 16 种提升。可以先枚举所有 64 个 $1\times2$ 域矩阵，再为每个矩阵检查这 16 种候选，每个 $Q$ 共 1024 次候选评估。

相反，若改成 $2\times2$ 域矩阵，就有 $8^4=4096$ 个矩阵，每个有 $2^8=256$ 种提升；单个 $Q$ 已超过一百万次评估。因此，完整枚举先限于上述更小情形，较大的形状使用预先固定的样本集。

样本中包含零矩阵、单位矩阵、置换矩阵、重复行和随机矩阵。这些不是都用于真实编码，而是分别检查零成本、接线、复用和一般结构。

### 4.2 做两组不同的计算

**第一组：枚举提升，固定调度器。** 对全部 $G$ 使用同一个调度器，分别求分阶段电路和允许跨投影边界优化的电路，比较候选分布、最好值和当前最小系数重量策略的位置。

它能回答：局部稀疏度目标是否错过了更好的候选？有没有一些 $Q$ 或提升能改善该调度器的结果？完整枚举保证覆盖了这一组有限候选，但不保证调度器找到了各候选的最优电路。

**第二组：对最小实例精确求原变换的 XOR 最优值。** 采用完整覆盖该成本模型的枚举、SAT 或其他精确综合方法，允许中间变量共享、任意合法 XOR、常量零和输出别名。

证明一个实例的最优值为 $c$，需要同时具备：一条 $c$ 门的正确电路，以及不存在更少门电路的可核查证明。求解超时或只找到一条电路时，只报告上界，不报告已经最优。矩阵秩本身也不是 XOR 门数下界：单位矩阵可以满秩，但需要 0 次 XOR。

将直接启发式成本和环成本都与这个精确值对照，观察谁更接近最优。若某个候选单独调度的最优值也能在预算内求出，可以进一步区分表示限制和调度误差，但不要求对所有候选都完成精确综合。

### 4.3 留下一份“收益实例证书”

一旦发现优于指定直接基线的实例，保存：

- $P,Q,A,G$，以及标准输入、输出坐标约定。
- 原矩阵 $T_A$、中间矩阵 $B_G$、投影 $D_m$。
- 直接基线和环路线的完整电路、各自成本及搜索预算。
- 矩阵恒等式检查和调度符号执行结果。

这是一份可独立重放的存在性证据。描述为“该实例优于某基线”，不能写成“少于原变换的真正最优 XOR 数”。

**阶段判据：** 优先寻找可解释、可重放的改善实例。若有限小范围内没有改善，记录搜索覆盖范围；先检查环选择与搜索目标，再决定是否扩大实验。即使所有环候选都未击败精确最优值，也不能据此否定本想法，因为本来就不可能击败它。

## 5. 阶段三：区分收益究竟来自哪里

先固定原域多项式、坐标表示、编码矩阵、调度器和随机种子；每组实验尽量只改变一个因素。

### 5.1 至少保留这些对照路线

| 路线 | 做法 | 主要回答的问题 |
|---|---|---|
| 直接逐行计算 | 在 $T_A$ 上独立计算每个输出 | 仅作为简单参照，不作为主要性能对手 |
| 强直接路线 | 对 $T_A$ 使用全局 CSE、修复后的 Uber／X-Sets 等，允许公平的随机重启与坐标置换 | 原路径在相同预算下本来能做到多好？ |
| 环内不改变系数 | 全部 $g_{ij}=0$，仍在模 $PQ$ 的环中计算并投影 | 仅改变中间约简环境有什么影响？ |
| 随机提升 | 随机选择各位置 $g_{ij}$ | 收益是特定选择策略，还是随机搜索也能获得？ |
| 当前策略 | 每个系数选择最小汉明重量的提升 | 当前局部目标是否有用？ |
| 子块重量策略 | 最小化 $n\times w$ 乘法块的重量 | 更接近 bitmatrix 的代理目标是否更好？ |
| 矩阵级搜索 | 按完整可验证电路的成本搜索 $G$ | 联合选择能否利用跨系数共享？ |
| CRT 结构策略 | 选择辅助分量为零、重复或低秩的矩阵 | 辅助分量的结构是否诱导共享？ |

强直接路线允许使用多种调度器，但它们共享该路线的总预算。环路线若采用多种调度器，也遵守同样规则。确定性的直接算法不能通过无意义地重复同一次运行消耗预算；可使用不同随机打破平局、输入／输出坐标置换及有意义的调度策略。

### 5.2 提升粒度与投影方式的消融

对有希望的策略继续比较：

1. 按系数值固定提升，与按矩阵位置独立选择提升。
2. 独立调度 $B_G$ 和 $D_m$，与保留中间结构并联合优化整个电路。
3. 仅优化主计算的成本，与完整计入输入转换、投影和输出转换后的成本。

第 3 项的前者只用于诊断“改善被哪一段开销抵消”，不能作为净收益结果。

联合优化时，要允许消去不必要的中间量和跨阶段抵消，但最后仍必须输出原编码结果。只计算 $D_mB_G$ 得到同一个 $T_A$ 再重新运行原调度器，不属于利用提升结构的联合优化。

### 5.3 用非环的冗余表示作为扩展对照

在最有希望的少量实例上，还可以直接搜索

$$
B=J_mT_A+K_mH,
$$

其中 $J_m$ 是标准补零，$K_m$ 的列生成投影的核。该形式的任何 $B$ 都满足 $D_mB=T_A$。

这是比逐系数环提升更宽的候选空间。把它作为预算相同的扩展对照，可以研究：环乘法的结构限制是否有利于高效搜索，还是一般辅助线性量也能取得相似结果。

它不是第一轮必做项目；更大候选空间可能难以搜索。一次启发式比较的胜负不代表两个候选空间的理论包含关系发生了变化。

### 5.4 不只记录一个 XOR 数

每个候选至少记录：系数重量、bitmatrix 重量、逐行成本、最终总 XOR、投影成本、被多个后续节点使用的临时量数量、最大 XOR 深度、最大存活临时量数量，以及搜索时间。

在 CRT 解释适用时，还记录辅助分量结构。若 $Q$ 不可约，可以考察辅助系数矩阵在 $\mathbb F_{2^r}$ 上的秩；若 $Q$ 可约，应改用明确定义的二进制线性展开等指标，不能直接沿用域矩阵秩算法。

选取正收益、负收益和接近持平的各若干实例，逐条解释最关键的共享或抵消。不仅分析赢家。

**阶段判据：** 能用配对对照解释改善来自哪项选择，并确认完整投影后仍有改善。若同预算的直接搜索消除了差距，结论应收缩为某种候选构造或搜索启发式的价值。

## 6. 阶段四：覆盖维度、环与实际编码矩阵

### 6.1 参数与环结构

| 范围 | 建议参数 | 用途 |
|---|---|---|
| 小规模结构研究 | $w=2,3,4$，$r=1,2,3$ | 枚举、精确校准与机制观察 |
| 主要编码实验 | $w=8$，$r=1,2,3,4$ | 比较 8 位域到不同环维度，避免只盯住 8→10 |
| 后续扩展 | $w=16$，先试少量小矩阵与小 $r$ | 观察是否能扩展，预算不足时单独报告 |

固定 $P$ 后，每个次数为 $r$ 的首一二进制多项式共有 $2^r$ 种。对 $r=1,2,3,4$，一共有 30 个 $Q$ 候选，可用廉价指标先筛选，再对入选候选做完整电路优化；筛选也计入搜索成本。

覆盖不可约 $Q$、可约且无重因子的 $Q$、有重因子的 $Q$。不要默认只有不可约 $Q$ 才合法。

对不可约 $P$，如果 $r<w$，所有这些 $Q$ 都与 $P$ 互素。因此“不互素环”不能混称为已经被上述 8 位主实验覆盖。另在小域设置 $Q=P$、即 $r=w$ 的专门组，研究模 $P^2$ 的情况；较大域是否扩展该组，由预算决定。

第一轮先固定原域多项式和多项式基，隔离环提升的作用。不同原域多项式和其他基放到扩展实验中；比较相同输入输出任务时，明确计入表示转换，并给直接路径相同的表示优化机会。

### 6.2 另设一组有结构的环，避免只搜索“稍微升维”

除了遍历小 $r$，还应主动构造有计算结构的模数。例如，若 $P$ 整除 $t^L+1$，可以选择

$$
M=t^L+1,\qquad Q=(t^L+1)/P.
$$

在这个环里 $t^L=1$，乘以 $t$ 就是 $L$ 个多项式坐标的循环移位。对纯 XOR 电路模型，它只是接线置换；乘以少数几个单项式之和，可以分解为这些置换结果的 XOR。

一个适合第一轮手算与实验的例子是

$$
P=t^4+t^3+t^2+t+1,\qquad Q=t+1,\qquad M=t^5+1.
$$

这里 $P$ 不可约，原域是 $\mathbb F_{16}$，环只有 5 个二进制坐标。每个系数可选 $a$ 或 $a+P$：在 5 位表示中，它们互为逐位补码，因此至少一个候选至多有 2 个 1。这给出了明确的结构性机会，但仍须计算完整输出和投影成本才能判断净收益。

这种机会取决于 $P$ 的结构。设 $\alpha=[t]_P\ne0$ 的乘法阶为 $s$，则 $P$ 整除 $t^L+1$ 当且仅当 $s$ 整除 $L$。若 $P$ 是本原多项式，$s=2^w-1$，最小的这种 $L$ 可能很大；换成其他不可约多项式可能改变该阶，但若改变了既定数据表示，就要计入转换成本。

所以，有结构的环与低冗余的环应作为两条独立路线。循环移位在抽象电路中免费，也不代表在实际软件数据布局中免费；这部分留到工程阶段测量。

### 6.3 编码矩阵不能只用逆 Vandermonde 方阵

主要确认集使用真正的 $m\times k$ 校验矩阵，考虑以下两类可构造、可验证的 MDS 编码：

- **系统化 RS：** 选择 $k+m$ 个不同求值点，生成 $(k+m)\times k$ Vandermonde 矩阵 $V$。令 $V_0$ 为前 $k$ 行，构造 $G=VV_0^{-1}$，取后 $m$ 行作为 $A$。要求 $k+m\le2^w$。
- **Cauchy：** 选择互不相同且两组不相交的 $u_i,v_j$，令 $a_{ij}=(u_i+v_j)^{-1}$。要求 $k+m\le2^w$。

保留当前的逆 Vandermonde 方阵作为旧实验回归样例；随机矩阵、重复行和稀疏人工矩阵作为结构诊断组，单独汇报，不与真实编码收益混合统计。

对小规模编码检查全部允许的擦除集合，对较大编码使用构造性质保证，并补充随机擦除恢复测试。恢复可使用原有限域解码器，不假设提升后的环矩阵可逆。

### 6.4 分开探索集和确认集

建议的起点是：

1. 探索集采用 $(k,m)=(4,2),(8,3)$，两类 MDS 构造各取 3 个预先生成的实例，共 12 个，用于选择搜索策略和预算。
2. 冻结策略后，确认集采用 $(4,2),(8,2),(8,3),(16,4),(32,6)$，两类构造每种规模各取 10 个新实例，共 100 个。
3. 随机诊断矩阵与当前仓库样例单独运行，数量和种子预先登记。

求值点或 Cauchy 参数由固定种子生成，保存完整矩阵；确认集不能只挑选探索时表现好的系数结构。确认集中若需要调参，应将其转为探索数据，并另生成确认集。

策略可以针对每个新矩阵在固定预算内离线优化，因为这正是方法的使用方式；不能依据确认结果再挑选只适用于赢家的全局规则。

### 6.5 汇报方式

令

$$
\Delta C=C_{\rm direct}-C_{\rm ring},\qquad
\eta=\frac{C_{\rm direct}-C_{\rm ring}}{C_{\rm direct}}.
$$

对每个矩阵都报告绝对差值和相对变化；直接成本为零时，比例记为不适用，不删除该实例。

这里的 $C_{\rm direct}$ 指相同预算下的强直接路线，不是逐行独立计算的弱参照。

分别按构造类型和规模报告胜／平／负数量、改善中位数、最差退化和成本比值分布。配对的实验单位是同一个编码矩阵；多次种子重启不当作多个独立编码实例。

如计算置信区间，按矩阵实例做配对重采样，并保持各构造／规模分层。它描述所设采样分布下的不确定性，不证明对所有编码矩阵成立。

### 6.6 对照相关方法，明确贡献在哪一层

在正式确认前，整理已有的域基选择、复合域表示、循环商环／阵列码实现，以及通用 XOR 电路综合方法。重点核对它们利用了什么代数结构、是否需要额外坐标、是否计入投影，以及采用什么输入输出布局。

对比时分成两类：计算完全相同 $A$ 的实现，可以作为直接性能基线；使用不同编码矩阵或不同存储冗余的码，只能在明确匹配码参数、可靠性和工作负载后，作为另一层系统对照。不能把改变编码任务得到的收益归因于同一矩阵的环提升。

## 7. 阶段五：验证收益能否抵消搜索代价

### 7.1 把搜索过程本身画出来

记录累计搜索时间对应的最佳可验证总 XOR，绘制“时间—电路成本”曲线。比较 1 秒、10 秒、60 秒检查点，而不只比较最终最好的一次结果。

每次找到候选时都保存正确性状态。超时但已有正确电路的运行可返回该电路；没有正确电路时记为失败，不按零成本比较。

以完整电路成本作为最终评分。可使用子块重量等廉价指标筛选，但要通过小规模枚举估计其漏掉好候选的程度。

矩阵级搜索先采用容易解释的坐标下降：每次尝试改变一个位置的 $g_{ij}$，评估候选总电路成本，配合有限次随机重启。若单位置搜索停滞，再在探索集研究两位置扰动、退火或其他策略，不一开始混入大量不可归因的算法。

### 7.2 离线成本怎样摊销？

设环方案比直接方案额外花费离线搜索时间 $T_{\rm extra}>0$，每次同规模编码调用节省 $\Delta t>0$，则在忽略其他费用时，需要大约

$$
N_{\rm break-even}=\left\lceil\frac{T_{\rm extra}}{\Delta t}\right\rceil
$$

次调用才能摊销。若没有实测每次编码的时间改善，不能仅凭 XOR 数计算这个摊销次数。

对长期固定编码矩阵和频繁更换矩阵的场景分别评价。若每次恢复都需要一个新解码矩阵，应将其视为另一个应用场景，重新计算搜索与复用条件。

## 8. 阶段六：从电路收益到实际编码性能

这一阶段只对已经通过符号检查、且有代表性的候选生成实际执行代码。候选应包含正收益、持平和少量退化例，避免只验证最好的一条。

### 8.1 两层性能测试

**电路内核：** 直接电路与环电路使用相同的位切片／数据包布局，相同字宽、向量指令和编译选项，比较指令数量、时间、寄存器溢出、最大临时存储与可利用并行度。该层尽量隔离布局转换。

**端到端编码：** 输入、输出采用相同的真实缓冲区布局，计入实际发生的数据变换、环中间缓冲、投影和输出写回。如果方案需要额外的拷贝，这些时间也包含在内。

再与使用相同原域多项式、输出相同字节结果的成熟 GF-Complete／Jerasure 等实现比较。该对照回答工程实用性，不能把它与“相同调度后端下的环机制实验”混成一个结论。

### 8.2 建议工作负载与测量规则

- 数据块先试每输入分片 4 KiB、64 KiB、1 MiB，分别观察小块开销与大块吞吐；明确报告大小指每分片还是总输入。
- 固定编译器、优化选项、CPU 型号、指令集和线程数，记录绑核与频率策略。
- 预热后至少做 30 组交替顺序的配对测量，记录原始时间与中位数，避免总是先跑同一路线。
- 运行时间使用真实运行时数据，并通过输出校验或消费输出避免编译器删除计算。
- 所有实现输出逐字节一致，且能由原有限域解码器在指定擦除情况下恢复。

只对中间环值使用 $n$ 位坐标时，单份对应中间缓冲的位数比例为 $n/w$；这不是整个系统存储或内存流量的固定增幅。实际应统计分配、读写和临时值的存活情况。

**工程判据：** XOR 少但吞吐持平或下降，应报告“电路复杂度改善，尚无软件速度收益”；只有端到端计时改善，才能声称该工作负载下编码更快。

## 9. 阶段推进与收缩条件

| 阶段 | 主要交付物 | 继续推进的依据 | 需要收缩或修正的情况 |
|---|---|---|---|
| 一：正确性 | 独立参考实现、矩阵与调度验证器、回归样例 | 输出一致且计数可信 | 任何未解释的错误都先阻止性能结论 |
| 二：小规模 | 候选枚举结果、部分精确最优值、收益实例证书 | 找到可解释改善，或明确知道搜索卡在哪里 | 未找到改善时先分析有限搜索范围和代理目标 |
| 三：机制 | 提升、投影、预算等消融报告 | 改善在公平对照后仍存在 | 若只击败弱基线，降低结论强度 |
| 四：确认集 | 多族实际编码的全部配对结果 | 改善具有跨实例稳定性 | 若只在人工矩阵有效，限定应用范围 |
| 五：搜索经济性 | 时间—成本曲线与摊销分析 | 额外搜索成本适合目标场景 | 若直接路线同预算已赶上，重点转向搜索机制 |
| 六：工程 | 内核与端到端吞吐、内存和恢复测试 | 实际工作负载得到净性能收益 | 若只有 XOR 收益，保留电路结论 |

可以预先登记一个工程筛选门槛，例如确认集净 XOR 改善中位数至少 5%、端到端吞吐改善至少 5%。这只是决定是否继续投入的项目标准，须结合实际噪声和场景要求，不是数学可行性的定义。

零星的 1 次 XOR 改善也可以是有效存在性证据；但若不足以覆盖工程成本，应明确把它与应用价值分开。

## 10. 最先执行的最小闭环

不必一开始跑完整参数网格。推荐首先完成以下一轮：

1. 建立独立验证器，处理当前优化器已知问题，复现旧的 8→10 样例。
2. 在 $w=3,k=2,m=1,r=1,2$ 上枚举提升，用同一调度器比较系数重量、子块重量和完整电路评分。
   同时加入第 6.2 节的 $\mathbb F_{16}$ 到 5 维循环环，检查有结构的模数是否比单纯追求低冗余更有希望。
3. 对极小实例求原变换的精确最优值，检查所有成本模型是否一致。
4. 对 12 个探索用 MDS 矩阵先比较直接路线、当前策略和按位置的矩阵级搜索；先限定 $r=1,2$，再扩大 $Q$ 和 $r$。
5. 保存一份改善实例或一份结构清楚的失败分析，决定后续重点是环选择、提升搜索，还是跨投影优化。

这轮的主要产出是一条可信、可重复、可解释的实验链，而不是预设必须得到正结果。

## 11. 实验记录与后续实现边界

每次运行至少保存：源码提交号、参考实现版本、硬件与编译配置、$P,Q,w,r,k,m$、完整矩阵与哈希、提升选择、种子、时间预算、搜索历史、各阶段矩阵、最终电路、总成本和验证结果。

建议后续实现分成四个职责明确的模块：独立代数参考、矩阵与电路验证、候选搜索与调度适配、运行器与结果汇总。验证模块不依赖搜索器报告的正确性标记。

具体数据文件可使用 JSON 保存单次配置与证据索引、JSONL 保存搜索历史、CSV 保存汇总指标。大型电路和矩阵独立存放并记录哈希。失败和超时也保留记录。

最终报告至少应包含：

1. 一份完整可重放的实例解释，包括基线与所有转换成本。
2. 多维参数与编码家族的配对结果，包含失败与退化。
3. 预算公平的时间—成本曲线。
4. 提升选择和投影处理的消融结果。
5. 若进入工程阶段，内核与端到端计时及内存开销。

本文交付的是验证设计，以上模块、搜索与大规模基准属于后续执行内容。实验结论应随着证据逐层建立，不把设计中的预期写成已经观察到的事实。
