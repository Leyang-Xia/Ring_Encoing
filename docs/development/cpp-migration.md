# C++ 整理与迁移约定

目标是保留研究结论及全部可检查的线路证据，将实现统一为 C++17，取消 Python 运行依赖。

- `include/ringlab/` 与 `src/`：共享的多项式、矩阵、任意长度比特向量、线路、CSE、实验与进程管理。
- `apps/`：统一的 `ringlab` 命令行，提供 `verify`、`profile`、`search`、`compare`、`analyze`。
- `data/certificates/`：原始 JSON 证据，原样保留，包括超时、负例和未决状态。
- `third_party/`：保留版权声明的 X-Sets 与 Uber 后端；X-Sets 源码保持原样。
- `legacy/`：早期依赖 Jerasure / GF-Complete 的演示程序，记录局限，不作为推荐入口。
- `docs/`：数学基础、验证方法、实验解释；README 只介绍项目、构建和导航。
- `tests/`：独立正确性检查及证据回归；不以关闭断言的方式影响验证。

使用 GNU Make 和 C++17 编译器构建，不引入第三方 JSON 或大整数依赖。JSON 中的大整数必须精确保留，不能先转浮点数；线路比特向量不能限定为 64 位。保留旧 CSE 的种子与随机选择语义，直接核对历史直方图及具体线路。

验证同时检查每条 XOR、最终输出、死门计数、两条路径的矩阵恒等式、所有所需 MDS 子式及随机输入；小例穷举 65,536 个输入。投影与进入环的实际成本遵守原始输入约定，最终按存活线路计数。有限启发式结果不得写成最优性证明，超时不得写成收益。

未来新增可执行逻辑使用 C++。历史 C 程序保留为归档，不扩展它；新能力进入共享核心及统一 CLI。

## 迁移核验记录

五个 Python 程序已迁移至共享核心和 `ringlab` 的 `verify`、`profile`、`search`、`compare`、`analyze` 入口。原有五份 JSON 证据及 X-Sets 源码与迁移前逐字节相同，数学基础文档保持原文。旧演示源码归档至 `legacy/`，已有本地产物收进忽略目录 `results/legacy-import/`。

本次通过的核验包括：

- GNU Make 全套测试、CMake Release 的 4 项 CTest、ASan/UBSan 全套测试及独立 Uber 内存访问回归。
- 与迁移前四组验证报告逐项比较；重现两组各 100 个 CSE 种子的直方图与选定线路，小例穷举全部 65,536 个输入。
- 超过 64 位的精确数值、非法节点与整数溢出、分解域基线、投影存活门复用、超时、取消及后端失败的回归检查。
- 原始证据与后端源码的字节比较、62 个本地 Markdown 链接、无 Python 源码及运行依赖检查。

CSE 保留历史选对、排序及随机种子语义，改为增量维护配对频率；线路执行优先使用连续数组，稀疏节点标签仍可执行。一次同环境计时中，旧四个验证入口合计约 6.74 秒，新统一入口约 0.77 秒，输出报告相同。这个数据只反映验证工具的单次开销，包含进程启动差异，不是编码吞吐或同预算搜索优势的测量。
